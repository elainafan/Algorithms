# 网络流：选板子、建图与恢复方案

这份说明面向已经会写基本图论代码的竞赛选手。比赛时先根据约束选求解器，再用后面的建图模型把原问题翻译成容量、费用或上下界。

## 快速选板子

| 问题 | 板子 | 主要接口 | 成功条件 |
| --- | --- | --- | --- |
| 最大流、最小割 | `Dinic.cpp` | `flow(s, t)`、`cut(s)` | `flow` 返回最大流 |
| 最多再流 `k` 单位 | `Dinic.cpp` | `flow(s, t, k)` | 返回值等于 `k` 时流满 |
| 普通二分图最大匹配 | `HopcroftKarp.cpp` | `work()` | 返回最大匹配数 |
| 无源汇上下界可行流 | `LowerFlow.cpp` | `feasible()` | 返回值不是 `nullopt` |
| 有源汇上下界可行流 | `LowerFlow.cpp` | `feasible_st(s, t)` | 返回值不是 `nullopt` |
| 上下界最大流或最小非负流 | `LowerFlow.cpp` | `max_flow(s, t)`、`min_flow(s, t)` | 返回值不是 `nullopt` |
| 最小费用最大流 | `MCMF.cpp` | `flow(s, t)` | 返回流量和对应费用 |
| 恰好 `k` 单位的最小费用流 | `MCMF.cpp` | `flow(s, t, k)` | 返回流量等于 `k` |

> [!IMPORTANT]
> `flow` 会修改残量网络。同一个对象上再次调用时，返回的是这一次新增的流量。`LowerFlow` 的每个求解接口都会重新建图，可以独立调用。

## 先确定容量表示什么

每条边的容量都应该对应原问题中的一个可加限制：

- 边最多使用多少次，直接把容量放在原边上。
- 点最多使用多少次，先拆点，再把容量放在拆点边上。
- 一个决策是否跨过分界，用最小割表示选择代价。
- 每增加一单位流量产生什么代价，把代价放在费用边上。
- 边必须至少使用多少次，用下界表示。

建图后要单独检查三件事：方向是否正确，容量是否少算或重算，无穷大是否真的不会成为最优割。

### 安全设置无穷大

将 `INF` 取为严格大于任意有限解代价上界的数。例如所有有限容量之和不超过 `sum` 时，可用 `sum + 1`。不要在后续还要做加法时盲目使用 `LLONG_MAX`。

## 常用建图积木

### 拆点限制点容量

将原点 `u` 拆成 `u_in` 和 `u_out`，添加 `u_in -> u_out`，容量等于该点的可用次数。原边 `u -> v` 改成 `u_out -> v_in`。

- 点不相交路径中，普通点的拆点边容量设为 `1`。
- 起点和终点允许重复使用时，它们的拆点边容量设为 `INF`。
- 最小点割中，拆点边容量就是删除该点的代价。

### 多源多汇与供需量

新建超级源 `SS` 和超级汇 `TT`。

- 对每个源点 `s_i`，添加 `SS -> s_i`，容量等于供给上限。
- 对每个汇点 `t_i`，添加 `t_i -> TT`，容量等于需求量。
- 若要求所有需求都满足，检查最大流是否等于总需求。
- 若源点无供给上限，对应边可以使用安全的 `INF`。

### 时间展开网络

将状态 `u` 复制到每个时刻，用 `(u, time)` 表示。一次转移用 `(u, time) -> (v, time + 1)` 表示，原地等待也要建边。

该模型适合限定时间内的运输、多个人同时移动、仓库库存和排班。建图前先估算点数与边数乘上时间范围后是否可承受。

## 最大流与最小割

跑完 `mf.flow(s, t)` 后，`mf.cut(s)` 返回残量图中从源点仍可达的点集。设返回数组为 `side`，原图中满足 `side[u] == 1 && side[v] == 0` 的边 `u -> v` 位于这组最小割上。

> [!NOTE]
> 恢复割边时要遍历自己保存的原边，不要把残量网络中自动生成的反向边当成原边。

### 最大权闭合子图

每个点 `i` 有收益 `w[i]`。若选择 `u` 就必须选择 `v`，建图如下：

- `w[i] > 0` 时添加 `S -> i`，容量为 `w[i]`。
- `w[i] < 0` 时添加 `i -> T`，容量为 `-w[i]`。
- 依赖 `u => v` 添加 `u -> v`，容量为 `INF`。

设所有正收益之和为 `positive_sum`，答案是

$$
\text{positive\_sum}-\operatorname{mincut}(S,T)
$$

最小割完成后，源点侧的原点就是被选中的闭合子图。

### 二元状态的最小割

将源点侧解释为状态 `0`，汇点侧解释为状态 `1`。对点 `i`，选状态 `0` 的代价为 `c0[i]`，选状态 `1` 的代价为 `c1[i]`，添加：

- `S -> i`，容量为 `c1[i]`。
- `i -> T`，容量为 `c0[i]`。

若 `i` 和 `j` 状态不同时额外支付 `w`，再添加 `i -> j` 和 `j -> i`，两条边容量都为 `w`。最小割正好计算一次该代价。

代价必须非负。任意的二元成对代价不一定能直接表示为最小割，只能在满足可割的子模条件时使用该方法。

## 二分图匹配及其对偶关系

纯二分图最大匹配优先用 `HopcroftKarp.cpp`。左部点和右部点各自从 `0` 编号，`hk.ml[u]` 和 `hk.mr[v]` 保存匹配对。

```cpp
HopcroftKarp hk(n_left, n_right);
for (auto [u, v] : edges) hk.add(u, v);

int matching = hk.work();
auto [cover_left, cover_right] = hk.min_cover();
```

`min_cover()` 必须在 `work()` 之后调用。它返回一组最小点覆盖，其大小等于最大匹配数。二分图最大独立集大小等于总点数减去最小点覆盖大小。

### DAG 最小路径覆盖

这里的路径覆盖要求每个点恰好属于一条路径，且原图必须是 DAG。

1. 将每个原点 `u` 拆成左部点 `u_L` 和右部点 `u_R`。
2. 对每条原边 `u -> v` 添加二分图边 `u_L -> v_R`。
3. 求最大匹配数 `matching`。

设原图点数为 `n`，最小路径覆盖数是 `n - matching`。恢复路径时，用匹配边确定每个点的后继，从没有匹配前驱的点开始走。

### Menger 定理与不相交路径

- 最大边不相交路径数等于最小边割。将每条可用一次的原边容量设为 `1`。
- 最大内部点不相交路径数等于最小内部点割。对普通点拆点，拆点边容量设为 `1`。

## 上下界流

每条边的流量要满足 `low <= flow <= high`。`LowerFlow::add(u, v, low, high)` 返回原边编号，各求解接口返回的边流数组与加边顺序一致。

```cpp
LowerFlow lf(n);
int id = lf.add(u, v, low, high);

auto circulation = lf.feasible();
auto any_st = lf.feasible_st(s, t);
auto maximum = lf.max_flow(s, t);
auto minimum = lf.min_flow(s, t);

if (minimum) {
    auto [value, edge_flow] = *minimum;
    cout << value << ' ' << edge_flow[id] << '\n';
}
```

- `feasible()` 求每个点都流量守恒的无源汇可行流。
- `feasible_st(s, t)` 求任意一组非负流值的有源汇可行流。
- `max_flow(s, t)` 求有源汇最大流。
- `min_flow(s, t)` 求有源汇最小非负流。
- 无解时返回 `nullopt`，不要只看流量数值判断可行性。

有源汇模型通过加入 `t -> s` 的回边转成可行环流。最大流在可行解上继续从 `s` 向 `t` 增广，最小非负流则在删除辅助边后从 `t` 向 `s` 退流。

`LowerFlow.cpp` 不处理费用。同时存在上下界与费用时，需要另行建立带点平衡的最小费用模型。

## 最小费用流

`MCMF.cpp` 支持负费用边，但要求从源点可达的正容量残量图中没有负费用环。

```cpp
MCMF mf(n);
mf.add(u, v, capacity, cost);

auto [flow, cost_sum] = mf.flow(s, t, k);
if (flow < k) {
    // 不存在恰好 k 单位的可行流
}
```

`flow(s, t)` 解的是最小费用最大流。`flow(s, t, k)` 只在返回流量等于 `k` 时，才给出恰好 `k` 单位流的最小费用。这两个问题的目标不同。

最大费用流可以将每条原边费用取反，跑最小费用流，最后将总费用取反。原费用不能是 `LLONG_MIN`，取反后仍要满足无可达负费用环的限制。

## 恢复边流、匹配与路径

### 边流与匹配

- `Dinic::add` 和 `MCMF::add` 都返回正向边编号。跑流后用 `get(id)` 取该原边的当前净流量。
- `LowerFlow` 的返回数组已经加回下界，不要再手动加 `low`。
- `HopcroftKarp` 用 `ml` 和 `mr` 直接恢复匹配对。

### 将整数流分解成路径

先保存所有原边的端点和边编号，再建立仅包含正流量原边的临时图。

1. 在临时图中找一条从 `s` 到 `t` 的正流路径。
2. 取路径上最小的剩余正流作为该路径流量。
3. 从路径上每条边的正流中减去该值。
4. 重复执行，直到不存在 `s -> t` 正流路径。

这会恢复所有 `s -> t` 路径部分。若原流中还有环流，最后可能剩下正流环。多数只要输出运输路径的题不需要处理这些环；若题目要求完整流分解，再从剩余正流边中提取环。

## 提交前检查

- 点编号是否全部转成 `0-based`。
- 无向容量边是否确实要建两条有向容量边。
- `INF` 是否大于任意有限割，又不会参与溢出。
- 需要恰好 `k` 单位流时，是否检查返回流量等于 `k`。
- 调用 `cut(s)` 前是否已经跑完最大流。
- 恢复方案时是否只遍历原边，并正确处理下界。
- 递归 `dfs` 的最坏深度是否可能超过运行环境的栈限制。

## 当前不收录的板子

当前不单独收录 Ford–Fulkerson、Edmonds–Karp、ISAP、ZKW 费用流和流分解代码。它们要么实战中已被现有板子覆盖，要么需要根据输出契约改写，单独复制的收益较低。

全局最小割、Gomory–Hu Tree、HLPP、带上下界的最小费用流和最小费用可行环流也未收录。遇到明确题型时再补对应实现，避免把低频且高风险的代码带进比赛。
