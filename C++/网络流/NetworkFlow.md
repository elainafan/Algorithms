# 网络流：选板子、建图与恢复方案

这份说明面向已经会写基本图论代码的竞赛选手。比赛时先根据约束选求解器，再用后面的建图模型把原问题翻译成容量、费用或上下界。

## 快速选板子

> [!IMPORTANT]
> 这些文件是配合个人比赛头使用的代码片段，不是独立编译单元。仓库当前不包含源码注释中的 `1.cpp`，复制时需要自行提供下列别名与工具。[`LowerFlow.cpp`](./LowerFlow.cpp) 还要求先复制 [`Dinic.cpp`](./Dinic.cpp)。

- [`Dinic.cpp`](./Dinic.cpp) 依赖 `ll`、`vi`、`vvi`、`all`、`sz`。
- [`HopcroftKarp.cpp`](./HopcroftKarp.cpp) 依赖 `vi`、`vvi`、`all`、`sz`。
- [`LowerFlow.cpp`](./LowerFlow.cpp) 依赖 `Dinic`、`ll`、`vi`、`vl`、`sz`。
- [`MCMF.cpp`](./MCMF.cpp) 依赖 `ll`、`i128`、`vi`、`vvi`、`pll`、`all`、`sz`。

| 问题 | 板子与接口 | 成功判定 | 复杂度与主要边界 |
| --- | --- | --- | --- |
| 最大流、最小割、最多再流 `k` 单位 | [`Dinic.cpp`](./Dinic.cpp)：`flow(s, t)`、`flow(s, t, k)`、`cut(s)` | 限制流量时返回值等于 `k` 才表示流满 | 一般图 `O(V^2 E)`；容量为非负 `ll`；`dfs` 递归深度可达 `V` |
| 普通二分图最大匹配、最小点覆盖 | [`HopcroftKarp.cpp`](./HopcroftKarp.cpp)：`work()`、`min_cover()` | `work()` 返回最大匹配数；`min_cover()` 要求先调用 `work()` | `O(E sqrt(V))`；左右部各自 `0-based`；递归深度最多为左部点数 |
| 上下界可行流、最大流、最小非负流 | [`LowerFlow.cpp`](./LowerFlow.cpp)：`feasible()`、`feasible_st(s, t)`、`max_flow(s, t)`、`min_flow(s, t)` | 在合法参数下，返回值不是 `nullopt` 才表示可行 | 继承变换后 Dinic 的复杂度；要求 `0 <= low <= high`；有源汇接口要求 `s != t` |
| 最小费用最大流、恰好 `k` 单位的最小费用流 | [`MCMF.cpp`](./MCMF.cpp)：`flow(s, t)`、`flow(s, t, k)` | 恰好 `k` 单位时，返回流量等于 `k` 才表示可行 | 初始势能最坏 `O(VE)`，之后每轮增广 `O(E log(V))`；保证范围见“最小费用流” |

> [!IMPORTANT]
> `Dinic::flow` 和 `MCMF::flow` 会修改残量网络。重复调用时，`Dinic` 返回本次新增流量，`MCMF` 返回本次新增流量与本次新增费用，不是累计值。`LowerFlow` 的每个求解接口都会重新建图，可以独立调用。

## 先确定容量表示什么

每条边的容量都应该对应原问题中的一个可加限制：

- 边最多使用多少次，直接把容量放在原边上。
- 点最多使用多少次，先拆点，再把容量放在拆点边上。
- 一个决策是否跨过分界，用最小割表示选择代价。
- 每增加一单位流量产生什么代价，把代价放在费用边上。
- 边必须至少使用多少次，用下界表示。

建图后要单独检查三件事：方向是否正确，容量是否少算或重算，无穷大是否真的不会成为最优割。

### 安全设置无穷大

将 `INF` 取为严格大于任意有限解代价上界的数。用 `sum + 1` 时，先以 `i128` 累加所有有限容量，再确认结果能放入 `ll`。

```cpp
i128 sum = 0;
for (ll cap : finite_caps) sum += cap;
assert(0 <= sum && sum < (i128)numeric_limits<ll>::max());
ll INF = (ll)sum + 1;
```

若有限解的上界本身已经无法用 `ll` 表示，这些板子的返回类型也无法安全表示答案。不要在后续还要做加法时盲目使用 `LLONG_MAX`。

## 常用建图积木

### 拆点限制点容量

将原点 `u` 拆成 `u_in` 和 `u_out`，添加 `u_in -> u_out`，容量等于该点的可用次数。原边 `u -> v` 改成 `u_out -> v_in`。纯点容量或最小点割模型中，该边容量设为安全的 `INF`；若原边本身也有容量限制，则保留它的真实容量。

- 点不相交路径中，普通点的拆点边容量设为 `1`。
- 起点和终点允许重复使用时，它们的拆点边容量设为 `INF`。
- 最小点割中，拆点边容量就是删除该点的代价。

### 多源多汇与供需量

新建超级源 `SS` 和超级汇 `TT`。

- 对每个源点 `s_i`，添加 `SS -> s_i`，容量等于供给上限。
- 对每个汇点 `t_i`，添加 `t_i -> TT`，容量等于需求量。
- 若要求所有需求都满足，检查最大流是否等于总需求。
- 若源点无供给上限，对应边可以使用安全的 `INF`。

### 时间展开网络

将状态 `u` 复制到每个时刻，用 `(u, time)` 表示。一次转移用 `(u, time) -> (v, time + 1)` 表示。只有题目允许在原地等待时，才添加 `(u, time) -> (u, time + 1)`。

该模型适合限定时间内的运输、多个人同时移动、仓库库存和排班。建图前先估算点数与边数乘上时间范围后是否可承受。

## 最大流与最小割

跑完 `mf.flow(s, t)` 后，`mf.cut(s)` 返回残量图中从源点仍可达的点集。设返回数组为 `side`，原图中满足 `side[u] == 1 && side[v] == 0` 的边 `u -> v` 位于这组最小割上。

> [!NOTE]
> 恢复割边时要遍历自己保存的原边，不要把残量网络中自动生成的反向边当成原边。

### 最大权闭合子图

每个点 `i` 有收益 `w[i]`。若选择 `u` 就必须选择 `v`，建图如下：

- `w[i] > 0` 时添加 `S -> i`，容量为 `w[i]`。
- `w[i] < 0` 时添加 `i -> T`，容量为 `-w[i]`。
- 依赖 `u => v` 添加 `u -> v`，容量为 `INF`。

设所有正收益之和为 `positive_sum`，答案是

$$
\text{positive\_sum}-\operatorname{mincut}(S,T)
$$

最小割完成后，源点侧的原点就是被选中的闭合子图。

### 二元状态的最小割

将源点侧解释为状态 `0`，汇点侧解释为状态 `1`。对点 `i`，选状态 `0` 的代价为 `c0[i]`，选状态 `1` 的代价为 `c1[i]`，添加：

- `S -> i`，容量为 `c1[i]`。
- `i -> T`，容量为 `c0[i]`。

若 `i` 和 `j` 状态不同时额外支付 `w`，再添加 `i -> j` 和 `j -> i`，两条边容量都为 `w`。最小割正好计算一次该代价。

代价必须非负。任意的二元成对代价不一定能直接表示为最小割，只能在满足可割的子模条件时使用该方法。

## 二分图匹配及其对偶关系

纯二分图最大匹配优先用 `HopcroftKarp.cpp`。左部点和右部点各自从 `0` 编号，`hk.ml[u]` 和 `hk.mr[v]` 保存匹配对。

```cpp
HopcroftKarp hk(n_left, n_right);
for (auto [u, v] : edges) hk.add(u, v);

int matching = hk.work();
auto [cover_left, cover_right] = hk.min_cover();
```

`min_cover()` 必须在 `work()` 之后调用。它返回一组最小点覆盖，其大小等于最大匹配数。二分图最大独立集大小等于总点数减去最小点覆盖大小。

### DAG 最小路径覆盖

这里的路径覆盖要求每个点恰好属于一条路径，且原图必须是 DAG。

1. 将每个原点 `u` 拆成左部点 `u_L` 和右部点 `u_R`。
2. 对每条原边 `u -> v` 添加二分图边 `u_L -> v_R`。
3. 求最大匹配数 `matching`。

设原图点数为 `n`，最小路径覆盖数是 `n - matching`。恢复路径时，用匹配边确定每个点的后继，从没有匹配前驱的点开始走。

### Menger 定理与不相交路径

- 最大边不相交路径数等于最小边割。将每条可用一次的原边容量设为 `1`。
- 当 `s` 与 `t` 不相邻时，最大内部点不相交路径数等于最小内部点割。对普通点拆点，拆点边容量设为 `1`，原边容量设为安全的 `INF`。

若 `s` 与 `t` 相邻，不存在只删除内部点的有限分割集。此时要根据题意单独计数直接边，或将每条原边容量设为 `1`，使每条直接边最多贡献一条路径。

## 上下界流

[`LowerFlow.cpp`](./LowerFlow.cpp) 只接受 `0 <= low <= high`，返回流量满足 `low <= flow <= high`。`LowerFlow::add(u, v, low, high)` 返回原边编号，各求解接口返回的边流数组与加边顺序一致。

```cpp
LowerFlow lf(n);
int id = lf.add(u, v, low, high);

auto circulation = lf.feasible();
auto any_st = lf.feasible_st(s, t);
auto maximum = lf.max_flow(s, t);
auto minimum = lf.min_flow(s, t);

if (minimum) {
    auto [value, edge_flow] = *minimum;
    cout << value << ' ' << edge_flow[id] << '\n';
}
```

- `feasible()` 求每个点都流量守恒的无源汇可行流。
- `feasible_st(s, t)` 求任意一组非负流值的有源汇可行流。
- `max_flow(s, t)` 求有源汇最大流。
- `min_flow(s, t)` 求有源汇最小非负流。
- 三个有源汇接口都要求 `s != t`；`s == t` 是不支持的参数，直接返回 `nullopt`。
- 在参数合法的前提下，`nullopt` 表示不存在相应的可行流。
- 容量、点平衡量、流量答案和计算它们的中间结果都必须能用 `ll` 表示。

有源汇模型通过加入 `t -> s` 的回边转成可行环流。最大流在可行解上继续从 `s` 向 `t` 增广，最小非负流则在删除辅助边后从 `t` 向 `s` 退流。

`LowerFlow.cpp` 不处理费用。同时存在上下界与费用时，需要另行建立带点平衡的最小费用模型。

## 最小费用流

[`MCMF.cpp`](./MCMF.cpp) 要求 `cap >= 0` 且 `cost != LLONG_MIN`。内部最短路和费用累加使用 `i128`，但返回总费用的类型是 `ll`，因此最终结果仍必须在 `ll` 范围内。

该实现只通过 `s -> t` 最短路增广，不会主动向答案中加入独立环流。它支持负费用边，但要求从 `s` 可达的正容量残量图中没有负费用环。检测到这类负环时，调试构建会触发断言；关闭断言后则返回 `{0, 0}`，不能把它当作普通的无流情况。

> [!WARNING]
> 若题目采用允许任意可行环流的标准最小费用定义，与 `s` 不连通的有限容量负环也可以降低总费用，而该实现会忽略它。要保证这一定义下的全局最优，调用 `flow` 前应保证整个正容量残量图不存在负费用环；若存在，需要改用负环消圈或最小费用可行环流算法。

```cpp
MCMF mf(n);
mf.add(u, v, capacity, cost);

auto [flow, cost_sum] = mf.flow(s, t, k);
if (flow < k) {
    // 不存在恰好 k 单位的可行流
}
```

`flow(s, t)` 解的是最小费用最大流。`flow(s, t, k)` 只在返回流量等于 `k` 时，才给出恰好 `k` 单位流的最小费用。这两个问题的目标不同。

最大费用流可以将每条原边费用取反，跑最小费用流，最后将总费用取反。原边费用不能是 `LLONG_MIN`，取反后仍要满足对应的负环限制。若 `flow` 返回的负总费用恰好为 `LLONG_MIN`，必须先转成 `i128` 再取反；正的最大费用将无法用 `ll` 表示。

```cpp
auto [flow, neg_cost] = mf.flow(s, t, k);
i128 max_cost = -(i128)neg_cost;
```

## 恢复边流、匹配与路径

### 边流与匹配

- `Dinic::add` 和 `MCMF::add` 都返回正向边编号。跑流后用 `get(id)` 取该原边的当前净流量。
- `LowerFlow` 的返回数组已经加回下界，不要再手动加 `low`。
- `HopcroftKarp` 用 `ml` 和 `mr` 直接恢复匹配对。

### 将整数流分解成路径

先保存所有原边的端点和边编号，再建立仅包含正流量原边的临时图。将求解器返回的非负净流值记为 `F`；若只有边流，则用源点总流出减去总流入计算 `F`。

1. 令 `extracted = 0`，在临时图中找一条从 `s` 到 `t` 的正流路径。
2. 设路径上的最小剩余正流为 `bottleneck`，本次提取 `min(bottleneck, F - extracted)`。
3. 从路径上每条边的正流中减去本次提取值，并累加到 `extracted`。
4. 重复执行，直到 `extracted == F`。若在此前已经找不到 `s -> t` 正流路径，边流记录不满足流量守恒，或 `F` 计算有误。

恰好提取 `F` 单位后，剩余正流在所有点上的净流量都为零，因此只会剩下环流。多数只要输出运输路径的题不需要处理这些环；若题目要求完整流分解，再从剩余正流边中提取环。

## 提交前检查

- 点编号是否全部转成 `0-based`。
- 无向容量边是否确实要建两条有向容量边。
- `INF` 是否大于任意有限割，又不会参与溢出。
- 需要恰好 `k` 单位流时，是否检查返回流量等于 `k`。
- 调用 `cut(s)` 前是否已经跑完最大流。
- 恢复方案时是否只遍历原边，并正确处理下界。
- 递归 `dfs` 的最坏深度是否可能超过运行环境的栈限制。

## 当前不收录的板子

当前不单独收录 Ford–Fulkerson、Edmonds–Karp、ISAP、ZKW 费用流和流分解代码。它们要么实战中已被现有板子覆盖，要么需要根据输出契约改写，单独复制的收益较低。

全局最小割、Gomory–Hu Tree、HLPP、带上下界的最小费用流和最小费用可行环流也未收录。遇到明确题型时再补对应实现，避免把低频且高风险的代码带进比赛。
